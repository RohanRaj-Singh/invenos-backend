## 1. Current Architecture Overview

### 1.1 Overall Assessment

The Clinic System is a **frontend-only prototype** with no backend persistence. All patient, visit, prescription, and treatment data lives in mutable JavaScript arrays in the browser's memory. The backend stubs exist but are not wired.

### 1.2 Backend Components

| Component | Status | Details |
|-----------|--------|---------|
| **Models** | ❌ Missing | No Patient, Visit, Prescription, or Treatment models exist |
| **Contact model** | ✅ Partial | Acts as patient via `roles: ['patient']` with `scopePatients()` |
| **ClinicService** | ❌ Broken | File exists at `app/Domains/Clinic/Services/ClinicService.php` with a namespace error (`$domain` literal) and empty class body |
| **ClinicController** | ❌ Missing | No controller — routes use closure-based Inertia renders |
| **Database tables** | ❌ Missing | No dedicated clinic tables — patients are contacts with a JSON role |
| **Migrations** | ❌ Missing | No clinic-specific migrations exist |
| **Routes** | ⚠️ Minimal | 3 GET-only routes, no POST/PUT/DELETE |
| **API endpoints** | ❌ Missing | No clinic API |

### 1.3 Frontend Components

| Component | Status | Details |
|-----------|--------|---------|
| **ClinicPage** (Patient List) | ✅ Complete | Search, stats, patient grid, "New Patient" dialog |
| **PatientProfile** | ✅ Complete | Tabs (Visits, Treatments, Prescriptions, Payments) |
| **NewVisit** | ✅ Complete | Diagnosis, medicines, billing, payment, completion dialog |
| **PatientHeader** | ✅ Complete | Gradient header, avatar, patient info |
| **VisitsTimeline** | ✅ Complete | Monthly grouped timeline with status badges |
| **TreatmentsHistory** | ✅ Complete | Treatment cards with progress bars |
| **PrescriptionsList** | ✅ Complete | Prescription cards with dosage/frequency/duration |
| **PaymentsOverview** | ✅ Complete | Outstanding stats + payment history |
| **AddMedicineDialog** | ✅ Complete | Product search + packaging selector + prescription fields |

### 1.4 Data Layer

The frontend data module (`resources/js/data/clinic.ts`) provides:

- **Mutable stores:** `mockPatients`, `mockVisits`, `mockTreatments`, `mockPrescriptions` — all populated from a deterministic generator
- **CRUD helpers:** `addPatient()`, `addVisit()`, `addPrescription()` — push to mutable arrays
- **Query helpers:** `getPatientVisits()`, `getPatientTreatments()`, `getPatientPrescriptions()`, `getPatientPayments()`
- **Contact sync:** `addPatient()` also pushes a matching Contact with `roles: ['patient', 'customer']` to `mockContacts`

### 1.5 Data Generator

The clinic data is generated by `resources/js/data/generator.ts` alongside all other mock data. Deterministic seed (42) produces:
- 20 patients with names, phone numbers, blood groups, registration dates
- 40 visits spread across patients with varying statuses
- 20 treatments with progress tracking
- 40 prescriptions with dosage/frequency/duration

### 1.6 Key Finding: All Data Is Ephemeral

**Everything resets on page refresh.** This is by design (the system is a frontend prototype), but means the clinic system has:

- No patient records after refresh
- No visit history
- No prescription history
- No treatment tracking
- No revenue data from clinic visits
- No connection to inventory (stock is never actually deducted for clinic prescriptions)

## 6. Prescription Image Feature Design

### 6.1 Data Model

```
prescription_images
━━━━━━━━━━━━━━━━━
id                  BIGINT UNSIGNED AUTO_INCREMENT
prescription_id     BIGINT UNSIGNED FOREIGN KEY → prescriptions.id
image_path          VARCHAR(255) NOT NULL    (storage path)
original_name       VARCHAR(255)             (original filename for download)
mime_type           VARCHAR(50)              (image/jpeg, image/png, application/pdf)
size                INT UNSIGNED             (file size in bytes)
is_primary          BOOLEAN DEFAULT FALSE    (first/cover image)
uploaded_by         BIGINT UNSIGNED FOREIGN KEY → users.id
created_at          TIMESTAMP
```

### 6.2 Storage Architecture

**Reuse the existing Laravel filesystem.** No Spatie Media Library needed at this stage.

```php
// config/filesystems.php
'disks' => [
    'prescriptions' => [
        'driver' => 'local',
        'root' => storage_path('app/prescriptions'),
        'url' => '/storage/prescriptions',
    ],
]
```

**File naming:** `{prescription_id}/{uuid}.{ext}` — UUID-based to prevent enumeration.

**Supported types:** JPEG, PNG, PDF (for lab reports), WEBP

**Max file size:** 10MB per image, max 5 images per prescription

### 6.3 Upload Flow

```
During NewVisit:
  │
  ├── Add Medicine → prescription fields + dosage
  │                     │
  │                     ▼
  │               [Upload Image] button
  │                     │
  │                     ▼
  │               File picker (click or drag & drop)
  │                     │
  │                     ▼
  │               Preview thumbnail
  │                     │
  │                     ▼
  │               [Add] → stores in temporary array
  │
  └── Save Visit → backend creates:
        • Prescription record
        • Moves temp files to permanent storage
        • Links images to prescription

After Visit:
  │
  └── Past visits → "Add Image" on existing prescription
```

### 6.4 Upload UI Integration

The upload should feel like a natural extension of the existing `AddMedicineDialog`:

```tsx
// Inside the prescription configuration view (after product + dosage):
<div className="border-t border-border pt-3">
  <p className="text-xs font-semibold text-muted-foreground tracking-wider mb-2">
    Prescription Image
  </p>
  <DropZone
    onFile={(file) => setWorking({ ...working, image: file })}
    preview={working.imagePreview}
    accept="image/*,application/pdf"
    maxSize={10 * 1024 * 1024}
  />
</div>
```

**States to handle:**
- **Empty:** Show drop zone with "Upload prescription image" prompt
- **Selected:** Show thumbnail with replace/remove buttons
- **Uploading:** Show progress indicator
- **Error:** Show error message with retry option
- **Multiple:** Show gallery of thumbnails with reorder

## 8. Media Architecture

### 8.1 Current State

**No media/upload infrastructure exists.** The project has:
- No filesystem disk configuration for uploads
- No storage symlink
- No upload controller or routes
- No image manipulation library
- No media/library package

### 8.2 Recommendation: Lightweight Upload System

**Do NOT introduce Spatie Media Library.** It's over-engineered for this use case. Instead:

1. **Storage driver:** Laravel local `storage/app/prescriptions/`
2. **Public access:** `php artisan storage:link` → `public/storage/prescriptions/`
3. **File naming:** `{prescription_id}/{uuid}.{ext}` — organized, unique, non-enumerable
4. **Validation:** Server-side: `mimes:jpeg,png,pdf,webp|max:10240` (10MB)
5. **Thumbnails:** Use Intervention Image (already common in Laravel ecosystem) if needed, but for MVP, serve originals with responsive `<img srcset>`
6. **Cleanup:** Delete files when prescription image record is deleted

### 8.3 Upload Endpoint

```
POST /api/v1/prescriptions/{id}/images
  Authorization: Bearer {token}
  Content-Type: multipart/form-data
  
  Request:
    image: File (required, max 10MB)
    is_primary: boolean (optional)
  
  Response (201):
    {
      "id": 1,
      "image_url": "/storage/prescriptions/1/uuid.jpg",
      "thumbnail_url": "/storage/prescriptions/1/uuid_thumb.jpg",
      "is_primary": true
    }

DELETE /api/v1/prescription-images/{id}
  Authorization: Bearer {token} (requires delete permission)

GET /api/v1/prescriptions/{id}/images
  Returns list of images for a prescription
```

## 9. Database & API Changes

### 9.1 New Table: `prescription_images`

```php
Schema::create('prescription_images', function (Blueprint $table) {
    $table->id();
    $table->foreignId('prescription_id')->constrained()->cascadeOnDelete();
    $table->string('image_path', 255);
    $table->string('original_name', 255)->nullable();
    $table->string('mime_type', 50)->nullable();
    $table->unsignedInteger('size')->nullable();
    $table->boolean('is_primary')->default(false);
    $table->foreignId('uploaded_by')->nullable()->constrained('users')->nullOnDelete();
    $table->timestamps();

    $table->index('prescription_id');
});
```

### 9.2 Existing Tables Referenced

- `prescriptions` — needs to exist first (currently only frontend mock data)
- `users` — already exists for `uploaded_by` FK

### 9.3 New API Routes

```
POST   /prescriptions/{id}/images        → PrescriptionImageController::store
GET    /prescriptions/{id}/images         → PrescriptionImageController::index
GET    /prescription-images/{id}          → PrescriptionImageController::show
DELETE /prescription-images/{id}          → PrescriptionImageController::destroy
GET    /prescription-images/{id}/download → PrescriptionImageController::download
```

### 9.4 New Model

```php
class PrescriptionImage extends Model
{
    protected $fillable = [
        'prescription_id', 'image_path', 'original_name',
        'mime_type', 'size', 'is_primary', 'uploaded_by',
    ];

    protected $casts = [
        'is_primary' => 'boolean',
        'size' => 'integer',
    ];

    public function prescription() { return $this->belongsTo(Prescription::class); }
    public function uploadedBy() { return $this->belongsTo(User::class, 'uploaded_by'); }
}
```

## Architecture Decision Summary

| Decision | Choice | Rationale |
|----------|--------|-----------|
| **Prescription Image storage** | Local filesystem (`storage/app/prescriptions/`) | Simplest approach, no external dependencies. Easy to migrate to S3 later. |
| **Media library package** | None (raw Laravel filesystem) | Avoids dependency overhead. The feature is simple enough without Spatie Media Library. |
| **Image serving** | Public symlink (`storage → public`) | Simple, no controller needed for GET. |
| **Permission model** | Spatie Permission (existing) | Reuses the existing system — no new RBAC. |
| **Upload during vs after visit** | During (in AddMedicineDialog) | Natural UX — doctor uploads while creating the prescription. Post-visit upload is secondary. |
| **Frontend state management** | Local state (consistent with app) | No Redux/Context needed. Images are per-prescription, not global. |
